# App Version with package_info_plus

Uses [`package_info_plus`](https://pub.dev/packages/package_info_plus) **10.x** — app name, package id,
version and build number at runtime.

| Android | iOS | macOS | Web | Linux | Windows |
|:-:|:-:|:-:|:-:|:-:|:-:|
| ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

## Steps

### 1. Add dependency
```bash
flutter pub add package_info_plus
```
No native setup. Requirements (met by this project): Flutter ≥ 3.38.1, Java 17, Kotlin 2.2, AGP ≥ 8.12.1,
iOS ≥ 13, macOS ≥ 10.15.

### 2. Read it
```dart
import 'package:package_info_plus/package_info_plus.dart';

final info = await PackageInfo.fromPlatform();   // cached after the first call

info.appName;         // "Flutter Best Practices"
info.packageName;     // "com.gucardev.flutterbestpractices"
info.version;         // "0.1.0"   ← pubspec `version: 0.1.0+1` (before +)
info.buildNumber;     // "1"       ← after +
info.buildSignature;  // Android signing cert SHA-256, '' elsewhere
info.installerStore;  // e.g. "com.android.vending" (Android/iOS), null elsewhere
info.installTime;     // DateTime?, null on web
info.updateTime;      // DateTime?, null on web
```
Before `runApp`, call `WidgetsFlutterBinding.ensureInitialized()` first.

### 3. In this project — `lib/profile/profile_page.dart`
**Profile tab → "Version 0.1.0 (1)"**:
```dart
class _AppVersionTileState extends State<_AppVersionTile> {
  late final Future<PackageInfo> _info = PackageInfo.fromPlatform();   // once, not in build

  @override
  Widget build(BuildContext context) {
    return FutureBuilder<PackageInfo>(
      future: _info,
      builder: (context, snapshot) {
        final info = snapshot.data;
        return ListTile(
          title: Text(info == null ? '…' : l10n.appVersion(info.version, info.buildNumber)),
          subtitle: info == null ? null : Text(info.packageName),
        );
      },
    );
  }
}
```

## Where the values come from

| Platform | Source |
|---|---|
| Android | `versionName` / `versionCode` from Gradle (`flutter.versionName/versionCode` ← pubspec) |
| iOS / macOS | `CFBundleShortVersionString` / `CFBundleVersion` (← `FLUTTER_BUILD_NAME/NUMBER`) |
| Windows | `ProductName`, `InternalName`, `ProductVersion` in `windows/runner/Runner.rc` (projects created before Flutter 3.3 must be migrated) |
| Linux | `data/flutter_assets/version.json` next to the executable |
| Web | `version.json` generated by `flutter build web`, fetched over HTTP |

Change the version in **one** place — `pubspec.yaml`:
```yaml
version: 1.4.0+27    # name+number
```
or override per build: `flutter build apk --build-name=1.4.0 --build-number=27`.

## Web notes
- `version.json` is fetched from the app's base URL; with a custom `--base-href` or a CDN pass
  `PackageInfo.fromPlatform(baseUrl: 'https://example.com/app/')`.
- Hosting with aggressive caching (e.g. Firebase Hosting) can serve a stale `version.json` or block it via CORS —
  set no-cache headers for it.

## Common uses
- "About" / settings screen, support e-mail body, bug reports.
- Forced update check: compare `info.version` with a minimum version from your backend.
- Don't use `packageName` for security checks — it's trivially spoofed on rooted devices.
